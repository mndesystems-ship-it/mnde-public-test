How trust works

Trust roots. MNDe signs every decision receipt with an Ed25519 key. A verifier trusts that key by holding the root fingerprint out of band — never from the receipt itself. In local development the root is a local dev key (LOCAL_DEV); in production it is a published custody root (VERIFIED) that you pin and distribute through a trusted channel.

Signing authority. Decisions are signed by a receipt key listed in the authority bundle, each with a validity window. Keys can be rotated and revoked (mnde-authority) without breaking historical receipts.

Receipt signatures. Verification re-runs the deterministic engine and checks the signature against the trusted authority — so a tampered request, policy, or decision fails closed. This works fully offline.

Recovery

If the protection light is red, the sidecar is unreachable or fail-closed — execution is not being gated. Restart MNDe (npm run sidecar) and this console reconnects automatically. A degraded runtime still fails closed (it refuses rather than allows).

Enterprise Identity

statusoptional · disabled
Entra ID, Okta, SSO, centralized policy, fleet, and shared audit are optional and off by default. Local protection requires none of them.
MNDe is local execution infrastructure — a firewall/runtime component, not a SaaS product. No login, no signup, no account, no cloud dependency.
